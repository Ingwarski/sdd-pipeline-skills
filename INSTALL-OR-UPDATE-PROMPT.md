# Єдиний промпт для встановлення або оновлення

Скопіюйте в локального агента з доступом до файлів і термінала:

```text
Встанови або онови SDD Pipeline Skills для локальних Codex і Claude Code: https://github.com/Ingwarski/sdd-pipeline-skills. Канал для студентів — stable, який проходить CI; не підміняй його main, якщо він недоступний.

Назви й шляхи бери зі skills-manifest.json вибраної ревізії, не зі старого списку. Зістав legacy_name → name: SDD to-prd → to-sdd-prd. Це перейменування того самого скіла: встановлюй актуальну назву без додаткового дозволу, навіть якщо старого скіла немає. Не створюй дубль; сторонній to-prd не змінюй. Невідому назву чи явну заборону перейменування уточни.

Спочатку без змін визнач ОС, активний Python і фактичні папки агентів за docs/installation.md. Знайди постійний клон у звичних папках проєктів за актуальним origin, старим Ingwarski/codex-skills або назвами Codex Skills / Codex SDD Skills. Не скануй весь диск і не перезаписуй сторонню роботу.

Для наявного клону перевір origin і локальну main; виконай git fetch origin stable. Якщо доступний scripts/installation_status.py, запусти його з --root CLONE, окремим --skill-root для кожного кореня агентів і --cleanup-root для додаткових підтверджених папок; для відомого проєкту додай --project PATH. Перевір також старі/проєктні корені за правилами інсталятора. «13/13» означає правильні посилання на цей клон і доступні вкладені ресурси, не просто файли SKILL.md.

Якщо git status --porcelain порожній, HEAD = FETCH_HEAD, links_result = current (або старий result = current) і Python підтримується: не запускай installer/updater і не оновлюй Python, але перевір сховище доказів через scripts/evidence_setup.py status з --project PATH для відомого проєкту. Налаштуй лише відсутнє сховище через ensure з тим самим --project за наступним абзацом; недоступне збережене місце чи облікові дані потребують відновлення, без підміни провайдера. Тоді повідом «Скіли вже актуальні» та коміт, окремо зазначивши стан сховища. Новішу Python зазнач лише як рекомендацію. Інакше перед інсталяцією/оновленням знайди останню стабільну Python 3 на python.org; якщо активна версія відсутня або старіша, встанови офіційну версію — цей промпт це дозволяє. Не замінюй системний Python. Пройди потрібне системне підтвердження, перевір активну версію; якщо це неможливо, зупинись. Після зміни Python повтори перевірку стану.

- Клону немає: git clone --branch stable URL CLONE, потім у клоні git switch -c main; ./install.sh --all або .\install.ps1 -All.
- Клон відстає або є communications-audit / issue-happypro-certificate: ./update.sh --channel stable --all або .\update.ps1 -Channel stable -All. Додаткові підтверджені корені передай через --cleanup-dir PATH / -CleanupDir PATH. Ці два скіли видаляються назавжди, без резервування чи Кошика.
- Ревізія актуальна, але встановлення невалідне: ./install.sh --all --repair або .\install.ps1 -All -Repair; сторонні конфлікти не перезаписуй.

Якщо старий клон не має updater/перевірки стану/параметра channel: спочатку чисте git merge --ff-only FETCH_HEAD, потім свіжі скрипти. Якщо застарілі копії заважають, використай повний тимчасовий checkout завантаженої stable-ревізії лише для installer --retire-only / -RetireOnly з вибраними коренями та явно доданим skills/ старого клону. Не відтворюй видалення вручну і не встановлюй посилання на тимчасовий checkout.

Після встановлення/оновлення або за відсутності налаштування виконай scripts/evidence_setup.py ensure; для відомого проєкту додай --project PATH. Якщо потрібен вибір, використай wizard. Прочитай docs/evidence-storage.md і запропонуй три варіанти: кероване локальне сховище поза Git; вибрана папка, диск або змонтоване сховище; Google Drive. У самому вікні/питанні вибору, ДО відповіді користувача, включи в опис варіанта Google Drive: «Для підключеного сховища в Codex спочатку встановіть Google Drive у Plugins і підключіть Google-акаунт; у Claude Code автентифікуйте Google Drive connector/MCP у Claude → Customize → Connectors, увійдіть у Code з тим самим Claude-акаунтом і перевірте /mcp. Rclone — необов’язкова альтернатива». В описах локального сховища й папки зазнач, що їм не потрібні ні цей плагін/конектор, ні rclone. Окреме повідомлення чи посилання на README не замінює опису в самому варіанті. Узгодь місце, сукупний робочий простір, ліміти проєкту/запуску/юніта, зберігання та прийняття наявних доказів/архіву. Збережений вибір використовуй без повторних запитань; змінюй лише за явною вимогою --reconfigure. SDD_EVIDENCE_HOME задає зовнішню папку конфігурації, а forge/evidence-policy.json зберігає переносні ID та політику без шляхів/секретів.

Не обирай хмарний обліковий запис, не завантажуй дані проєкту і не видаляй докази лише через інсталяцію. Після вибору та дозволу користувача перевір Google Drive реальним завантаженням синтетичних байтів і незалежним отриманням оригіналу; без цього не називай налаштування успішним. Якщо потрібна автентифікація, поясни єдиний крок користувача. Не встановлюй необов’язкові залежності без дозволу. Локальний варіант не потребує Google Drive або rclone. Якщо інтерактивність/можливість відсутня, повідом точний setup_required та команду, не підміняй провайдера.

Поясни: інша папка на тому самому диску прибирає засмічення Git, але не звільняє диск. Локальні згенеровані артефакти мають типовий строк 30 днів від початкового завершення; Google Drive потребує окремого вибору зберігання. Поточні докази приймання, базові матеріали, дозволи, невирішені помилки та імпортовані архіви захищені. GitHub Actions використовує окремі налаштування артефактів і журналів; локальний прапорець не перешкоджає хмарному видаленню. Приймай старі архіви через декларативний import без повторного завантаження, зберігаючи початкові каталоги/час. Не ігноруй forge/ або output/ цілком і не переписуй історію іншого репозиторію.

На чужому origin/не-main зупинись до очищення. На main дозволене лише вказане очищення; якщо після нього лишилися сторонні зміни чи HEAD попереду/розходиться зі stable — зупинись без reset, downgrade чи перезапису. GitHub недоступний — оновлення зупиняється; уже виконане очищення не приховуй. Дотримуйся AGENTS.md, інші скіли не змінюй. Повтори перевірку й коротко повідом клон, канал/коміт, перевірені корені, провайдера/стан сховища, результат, помилки, точні відсутні можливості та потребу перезапуску. Із збереженої конфігурації та політики повідом лише вибрані несекретні значення: місце, машинний типовий вибір чи прив’язка проєкту, повторно використано чи створено, сукупний локальний простір, місцевий строк і окремий строк Drive, результат запитаного прийняття архіву. Команди мосту та вміст облікових даних не виводь. Не перелічуй застарілі скіли в підсумку; помилки очищення повідом обов’язково. Не створюй фонових оновлень.
```

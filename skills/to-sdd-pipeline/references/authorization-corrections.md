# Recording an already-approved decision

A correction that only records an existing explicit user decision does not require approval again. Preserve the original implementation prompt and its timestamps. Reconcile affected owners, inspect the actual before/after diff, and retain the authorization using the verified record below. Initial implementation still requires an explicit prompt. New or uncertain scope, behavior, design, security, cost, acceptance, unit boundaries or permissions require the normal fresh-prompt path; a correction label cannot authorize them.

## Version 1 correction receipt

`implementation_gate.correction_receipts` is an optional ordered list of `{path, content_hash}` references. Keep the gate authorized with the current `development_plan_hash`, original prompt receipt/ID, original `awaiting_at`, `prompt_received_at` and `released_at`. Each referenced JSON contains:

- `event: approved_decision_documentation_correction`, `version: 1`, nonempty `author`, timezone-aware `recorded_at`, after the original release and no earlier than the preceding correction review.
- `from_plan_hash`, `to_plan_hash`: a continuous, noncyclic chain from the original prompt's plan to the current plan; each step changes the hash. No unused or branching steps.
- `approved_baseline_id` and `product_scope_hash`, equal to the original authorization (explicit null when absent). `baseline` contains the unchanged active `prototype_tree_hash` and `visual_target_hash`, or null for headless scope.
- `decisions`: nonempty hash-bound references to original/faithfully normalized JSON decisions, each with `event: approved_decision`, `role: user`, `decision_id`, original `message`, and `approved_at` no later than the original implementation prompt. Preserve original evidence and disclose unavailable host metadata; never invent an old approval to qualify.
- `source_snapshots`: the complete applicable canonical SDD output inventory, mapping each path to hash-bound immutable `before` and `after` file references. Include unchanged files. Every step’s entire before inventory must equal the preceding after inventory; the final inventory must match all current canonical bytes.
- The first receipt also requires `original_manifest`, a hash-bound actual archived manifest from before correction. Its artifact hashes bind the first before inventory, its authorized gate binds the unchanged original prompt and timestamps, and its unit/QA contracts agree with those snapshots. Later receipts cannot replace this anchor. Preserve real historical sources; do not fabricate convenient before versions. Without authentic prior evidence use the normal authorization path.
- `documents`: nonempty entries `{path, owner_skill, owner_invocation_id, decision_ids, before, after}`. Paths must be canonical SDD outputs; owner must match the pipeline contract. Before/after are hash-bound immutable file snapshots. Include exactly the changed inventory paths, including the plan, with matching snapshot references, unique paths and referenced decision IDs. The latest snapshot of each changed document must match its current canonical bytes and owner invocation. Corrections cannot include production source or configuration.
- `review`: a hash-bound JSON record with `event: documentation_correction_review`, nonempty `reviewer` distinct from `author`, `reviewed_at` between the correction time and now, `result: preserves_approved_intent`, `rationale`, and `documents` mapping exactly those canonical paths to `{before_hash, after_hash}`. Its `source_snapshots` binds every inventory path to `{before_hash, after_hash}`; its `decision_ids` exactly match the receipt's decisions. Its `unchanged` map has true values for `scope`, `behavior`, `design`, `security`, `cost`, `acceptance`, `unit_contract`, and `permissions`.

Owners verify the correction against the cited earlier decisions, including any prior omission. The independent reviewer examines the complete changed text and unchanged claims, not only structured JSON. The orchestrator records their return, retains the old authorization in history and runs the normal checker. Review is an execution duty, not another user approval. If provenance or semantic equivalence cannot be established, do not fabricate it; use the normal authorization path.

The checker verifies snapshots, owners, decision references/times, review bindings, chain continuity, unchanged baseline/scope and identical embedded unit/QA acceptance contracts across all before/after plan and QA snapshots. An old prompt that bound only the plan does not retroactively authenticate the other historical sources. The checker cannot authenticate people, archived history or prose semantics; a syntactically valid assertion is not sufficient owner/reviewer evidence. Missing, tampered, discontinuous or materially changed records fail closed. The baseline approval must predate the original implementation prompt. Current owner/source/baseline checks still apply.

## Verification remains separate

Preserving permission does not create, refresh or waive QA/DoD results. Keep actual runs, dates and source bindings. Re-evaluate affected evidence under the normal verification contract; preserve superseded runs separately. Never change old execution timestamps or hashes to imply a rerun. The exception grants no merge, deployment, spending, sequencing or new implementation authority. A later explicit implementation prompt may authorize the current plan directly without using this exception.
